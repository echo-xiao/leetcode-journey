借 flomo 的语法，说自己的话

这不是规则文档，是一张样张。页面上每一块颜色、每一个字号、每一次按下的反馈， 都是即将写进 Theme.swift 的那个值本身 —— 看到的就是会得到的。

本稿只定视觉。 确认之后再转成带 SwiftUI 常量的规则手册，并逐条比对现有代码。 所以现在只需要回答一件事：这套东西，看着对不对。

00三条公理

后面所有具体数值都是这三句话的推论。如果某个值和它们冲突，错的是值。

01

底色是浅灰，白是浮起来的东西

这是整套语言能在浅色模式下成立的根本。页面不是白的，卡片才是白的。一旦把底色做成纯白，所有层级会同时塌掉 —— 因为这套系统没有边框可以兜底。

02

一屏只有一个主角

实心绿块只出现一次，含义恒定：你在这里。它不做按钮、不做链接、不做强调文字。绿色一旦出现第二次，第一次就不再是指示，而变成了装饰。

03

没有线

全局零描边、零分割线。层级只由两件事表达：底色的明度台阶，和一条极柔的阴影。想画一条线的时候，真正需要的通常是 8pt 留白。

唯一的阴影

0 6px 20px rgba(27,35,31,.07) —— 浅色；深色换成 rgba(0,0,0,.45)。 只用在 L2 和浮层（药丸、FAB）。选中的绿块不加阴影，它靠颜色已经足够重。

02色板

中性色不是灰的 —— 它们统一偏向强调色的色相（约 148°），饱和度压在 3–6%。 这一点肉眼几乎读不出，但它让整屏颜色像是同一个家族，而不是拼来的。

四条用色铁律

1绿只表示位置。不做按钮底色，不做链接，不做强调文字，不做成功提示。
2热力图的绿必须更淡。它是氛围不是信息，最深一档才允许等于强调绿本身。
3蓝只做内联可点。标签 chip、「展开全文」。蓝绝不用于选中态。
4其余一切都是灰阶。没有第五个色相。需要区分难度 / 状态时，用灰度和位置，不用颜色。

05行

整个抽屉只有这一个构件。导航项、标签项、设置项共用同一副骨架 —— 所以所有行的文字起点落在同一条 x 轴上，包括选中的那一行。这条轴线就是抽屉的结构。

图标必须是实心填充式，颜色与文字同为 Ink 1。线性细描边图标会让左轴线变虚 —— 这是整个抽屉最先垮掉的地方。视觉尺寸统一 24，不同形状做重量补偿（圆形可略大，方形略小）。

行尾默认只放操作。有下一层才给 chevron，有菜单才给 ···，否则留空。 行尾堆数据会让每一行都在喊，整屏就没法扫。 唯一的例外是标签列表的进度计数（5/61）—— 见本节末尾， 那是你的产品比 flomo 多出来的信息，且只出现在那一处。

上面第四行是禁用态：整行 34% 不透明度，没有按下反馈。 不要用变灰来表示禁用 —— 变灰会和 Ink 3 的次要文字混淆。

选中态只有一种形态

实心圆角块，含义恒定：你在这里。不是下划线，不是左侧竖条，不是加粗，不是变色文字。 这四种替代方案的共同问题是重量不足 —— 在一个没有边框、全靠色块说话的系统里， 2px 的线撑不起「当前位置」这么重的语义。

层级：就地缩进展开，用一条竖线串起来

这一条推翻了本稿早先的写法。之前写的是「用 chevron 进下一屏，不用缩进」—— 那是只看到收起态截图推出来的。flomo 的展开态是就地缩进， 而且有一条竖向引导线。

子项不降级。和父项同字号、同颜色 —— 层级只由缩进和那条线表达， 不靠把文字变灰。把子项降到 Ink 2 会让它和「次要文字」混淆。

chevron 只是旋转，不换图标。收起 ›，展开转 90° 成 ⌄， 180ms。叶子节点没有 chevron，但保留那个位置的占位 —— 否则两级的行尾会错开半个字。

引导线的 x 由父行自己的内距推出来（行内距 + 图标槽 / 2）， 对齐父行 # 的中心。这样改行内距的时候线会自己跟上，不用记得去改第二个地方。

行尾是「计数 + chevron」两件事。这是本稿唯一允许在行尾放数据的地方 —— flomo 这里放的是 ···，但进度计数是你的产品比它多出来的信息， 且只在标签列表这一处出现，不构成 §5 说的「每一行都在喊」。

06维度切换器

flomo 没有这个构件，因为它不需要换个角度看同一批内容。你需要 —— 「题单 / 标签 / 公司 / 时间」是同一堆题的四种看法。所以这里要加一个 flomo 没有的东西， 前提是它得说这套语言。

判据：导航用颜色，维度用高度

这是整份设定稿里唯一需要记住的分类法。两个构件长得完全不同，因为它们回答的是两个问题。

构件回答的问题做了什么形态
行 · §5 我在哪里？ 换掉整屏的内容来源 实心绿块
切换器 · §6 我怎么看它？ 同一批内容，换一种组织方式 凹槽里的白浮片

把颜色留给导航，意味着公理 02 不受威胁 —— 一屏仍然只有一块绿。 切换器改用高度说话：L3 的凹槽 + L2 的浮片，正好是 §1 那套层级的复用， 一个新颜色都不用引入。而且它天然像个控件，有「可以拨」的手感。

等分铺满

四段及以上、且文字长度接近时，让每段等宽铺满容器 —— 比左对齐更稳，也更像一个整体。

Material / Web 的语汇。选中态压成一条 2px 的线，重量不足；而且它凭空引入了一条「线」—— 违反公理 03。另外这里的绿是全屏第二块绿，会削弱抽屉里那块真正的绿。

✓ 凹槽切换器

零新颜色、零线条，全部由已有的 L2 / L3 层级和 Ink 灰阶构成。重量足够读作主控件，又明显比绿块轻 —— 层次关系正确：先定位置，再选看法。

什么时候不要用它

超过 5 段、或者段数会随数据变化，就不该用切换器 —— 换成 §5 的行列表，或者一个下拉。切换器的前提是选项固定且一眼能数完。

触觉

克制使用，只在三处：切换选中项 .selection、 提交评分 .impact(.light)、 破坏性操作确认 .warning。 滚动、展开、翻页不给触觉 —— 滥用会让反馈完全失去意义。

无障碍

行高 40 低于 44 × 44 的触控下限 —— 用 contentShape 把可点区域外扩到 44，不要把行撑高。 支持动态字体，字阶按比例缩放，行高随之变化而不是裁切。 开启「减弱动态效果」时，全部转场降为即时切换。 选中态除了颜色还有 chevron 和 VoiceOver 的 .isSelected 标记 —— 不能只靠颜色区分状态。

一条明知故犯的例外

白字压在 #30CF79 上
组合对比度WCAG AA（正文 4.5）
白 #FFFFFF2.03 : 1不通过
近黑 #04220E8.33 : 1通过

我们选了白字，明知它不通过。理由是视觉上和 flomo 一致 —— flomo 自己在这一处也不通过。这是记录在案的取舍，不是遗漏： 看到它的人请不要当 bug 改成深色。

两点缓解。其一，失效的只是 1.4.3 对比度； 1.4.1「不以颜色为唯一手段」仍然成立 —— 选中态同时由实心块、chevron 和 VoiceOver 的 .isSelected 表达， 色觉障碍用户不依赖那抹绿也能判断自己在哪。 其二，整个应用里压着白字的绿只有选中行这一处（公理 02 的副产品）， 所以影响面是一个构件，不是一套文字系统。

要反悔只需改一个 token：--accent-ink 从 #FFFFFF 换成 #04220E，全局即刻生效。

09禁止事项

每一条都对应一个已经发生过、或者极容易发生的具体错误。

01纯白页面底色。会让三层结构同时塌掉。底色永远是 Ground。
02分割线与描边。包括列表分隔线、卡片边框、输入框边框。用留白和底色台阶。
03第二块绿。绿色在一屏里出现两次，第一次就失效了。
04下划线表示选中。以及左侧竖条、加粗、变色文字。导航选中只有实心绿块，维度选中只有凹槽浮片。
05线性细描边图标。和实心图标混用会让左轴线散掉。
06行尾堆数据。百分比、时间、状态都不行。唯一获准的是标签列表的进度计数（§5 末）。
07栅格外的数字。10、14、22、26 —— 一个破例会繁殖出十个。
08渐变、彩色阴影、毛玻璃。这套语言里不存在这三样东西。
09弹跳动效与超过 320ms 的转场。包括滚动计数器和入场交错动画。
10深色模式用反转得到。L3 在两个模式里都比 L2 暗；中性色要重新定，不是取补。
