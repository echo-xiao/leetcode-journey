# Kerno 果核 · 设计系统

> 2026-11-17 · 对应设计稿 `docs/design/leet-jounry-ui.html`
>
> 这份文档定义**数值和它们的名字**。组件长什么样看设计稿，为什么是这个数看这里。
> 两份不一致时，以这份为准——设计稿是实现，这份是规格。

---

## 0. 怎么用这份文档

### 三层结构

```
1  基元 (primitives)    原始值：色号、字号、间距数字
      ↓  只被第 2 层引用。产品代码永远不碰这一层
2  语义 (semantic)      --ink-2  --t-body  --accent  --s4
      ↓  产品代码只认这一层
3  组件 (components)    Row / Card / Button / Flag
```

### 铁律

**产品代码里不准出现裸值。** 看见 `#30CF79`、`font-size: 13px`、`padding: 16px`
就是漏了一层。唯一的例外是第 1 层自己的定义处。

这条不是洁癖。整个系统的价值就在于"改一处，全局跟着变"——只要有一个裸值，
它就会在下次改版时留在原地，变成一个没人记得为什么长这样的异类。文件里
现在那几个 `13.5px` / `11.5px` 就是这么来的。

### 命名约定

| 前缀 | 含义 | 例 |
|---|---|---|
| `--t-*` | type，字号 | `--t-body` |
| `--lh-*` | line-height，行高 | `--lh-body` |
| `--w-*` | weight，字重 | `--w-semi` |
| `--ink-*` | 文字色，数字越大越淡 | `--ink-2` |
| `--s*` | space，间距 | `--s4` |
| `--r*` | radius，圆角 | `--r3` |

语义名说的是**用途**不是外观。`--ink-3` 是"第三层文字"，不是"灰色"——
换深色模式时它自己会变成浅灰，名字不用改。`--gray-500` 就得全文替换。

## 1. 两个平台，一套系统

Chrome 侧边栏和 iOS app 是同一个产品，但**不共用数值**。

| 一份，改一处两端都变 | 两份，同名不同值 |
|---|---|
| 颜色 token | 字号刻度 |
| 品牌（logo、绿、文案语气） | 间距密度 |
| 语义名本身 | 点击区下限 |
| 图标风格、动效曲线 | 组件几何（内距、圆角） |
| 术语表 | 导航范式 |

关键在"语义名本身"这一行：两端都写 `--t-body`，iOS 解析成 16，面板解析成 13。
**代码长得一样，渲染出来是各自的母语。**

为什么不能统一数值：iOS 的 17pt 正文是给 390pt 宽、手持 35cm 定的；侧边栏
360px 在桌面上是另一个观看距离。统一之后面板会像"放大了的手机界面"，而且
跟面板自己的字阶打架。

实现方式——基准写在 `:root`（手机档），面板作用域里重新指派：

```css
:root {
  --t-display: 28px;  --t-hero: 26px;  --t-title: 18px;  --t-body: 16px;
  --t-reading: 14px;  --t-label: 13px; --t-meta: 12px;   --t-micro: 11px;
}
.panel {
  --t-display: 20px;  --t-hero: 20px;  --t-title: 15px;  --t-body: 13px;
  --t-reading: 13px;  --t-label: 12px; --t-meta: 11px;   --t-micro: 10px;
}
```

面板没有 display 这一档（没有大数字那种展示性内容），指向 hero 占位。

## 2. 颜色

### 2.1 语义层

| token | 含义 | 用在哪 |
|---|---|---|
| `--ground` | 最底层背景 | 页面底、面板底 |
| `--card` | 浮起的内容面 | 卡片、弹层、输入框 |
| `--inset` | 凹陷面 | 分段控件底、代码块、标题栏 |
| `--hair` | 1px 分隔线 | 行与行之间、卡片描边 |
| `--ink-1` | 主文字 | 标题、强调、唯一加粗的那个字 |
| `--ink-2` | 正文 | 卡片正文、说明 |
| `--ink-3` | 次要信息 | 时间、计数、未选中的导航 |
| `--ink-4` | **装饰，不承载信息** | placeholder、禁用态、空格子 |
| `--accent` | 品牌绿 | 主操作、选中态、热力图 |
| `--overdue` | 警示橙 | 逾期标记。调色板里唯一的警示色，不另造红 |
| `--hl` | 复盘高亮 | 正文里被标记的句子 |
| `--tag-bg` / `--tag-ink` | 标签 | 技术标签、公司标签 |

### 2.2 ink 梯 —— **本次修正**

实测结果：**深色模式全部通过，浅色模式后两档读不出来。**

| | 浅色现值 | 压白卡 | 深色现值 | 压深卡 |
|---|---|---|---|---|
| ink-1 | `#1B231F` | 16.07:1 ✅ | `#E6EEEA` | 14.34:1 ✅ |
| ink-2 | `#6A7670` | 4.73:1 ✅ | `#9AA59F` | 6.66:1 ✅ |
| ink-3 | `#A0AAA5` | **2.39:1 ❌** | `#717A75` | **3.82:1 ⚠️** |
| ink-4 | `#C3CCC7` | **1.64:1 ❌** | `#4B534F` | **2.14:1 ⚠️** |

ink-3 现在装着时间戳、计数、未选中的导航——**那些是信息**，2.39:1 等于没显示。

问题不是单点，是整条梯塌了。浅色的 ink-2 已经贴在 4.5 的地板上（4.73），
下面没有空间再放两档。所以 ink-2 必须上移腾位置。

**修正后：**

| | 浅色 | 压白卡 | 深色 | 压深卡 |
|---|---|---|---|---|
| ink-1 | `#1B231F` 不变 | 16.07:1 | `#E6EEEA` 不变 | 14.34:1 |
| ink-2 | `#525B57` | 7.02:1 | `#9AA59F` 不变 | 6.66:1 |
| ink-3 | `#6D7973` | 4.53:1 | `#78877F` | 4.49:1 |
| ink-4 | `#8C9792` | 3.02:1 | `#5E6A63` | 3.00:1 |

目标值是 **16 / 7 / 4.5 / 3**，不是随手调的：4.5 是正文的无障碍地板，
3 是大字和 UI 元素的地板，7 和 16 往上等距拉开。相邻档之间的对比在
1.48–2.29 之间，都 > 1.3，层级看得出来。

**代价要说清楚**：浅色模式的正文（ink-2）会比现在深一截，和当初照 flomo
量的灰会有偏差。这是必要的——我们的卡片底色和 flomo 不同，同一个灰在
这里压不住。品牌观感和"能不能读"冲突时，后者优先。

**配套规则**：ink-3 是**信息的下限**。任何用户需要读到的字，最淡只能到
ink-3。ink-4 只给装饰用——placeholder、禁用态、空热力格——而且永远不能
是某个意思的唯一载体。

### 2.3 强调色

品牌绿 `#30CF79` 在深色底上 9.23:1，没问题；**在浅底上 1.84:1，几乎看不见**。

所以绿色不是一个值，是三个用途：

| token | 值 | 用途 | 对比 |
|---|---|---|---|
| `--accent` | `#30CF79` | **填充**：按钮底、选中药丸、热力图 | — |
| `--accent-ink` | `#1B231F` | 压在填充上的字 | **7.90:1** ✅ |
| `--accent-text` | 浅色 `#1F874F` / 深色 `#30CF79` | 绿色的**字和图标** | 4.53:1 / 9.23:1 |

**这里推翻了设计稿里的一条旧决定。** 原来绿底配白字，记录在案是"2.03:1，
明知故犯"。实测下来 2.03 不是"将就"，是主操作按钮上的字读不出来。

正确解法不是把绿调暗（那会丢掉品牌色），是**把字翻成深墨**：填充仍然是
一模一样的 `#30CF79`，字色从白换成 `#1B231F`，对比度 2.03 → 7.90。
品牌一个像素没变，可读性从不合格到远超标准。

同理，其余强调色也要分浅深两版：

| | 填充/深底用 | 浅底的字用 |
|---|---|---|
| overdue | `#D97757` | `#C6522D` (4.52:1) |
| gold | `#BFA47A` | `#8F7245` (4.51:1) |
| tag-ink | `#8FA6F0` | `#3A64EB` (4.50:1) |

### 2.4 规则

1. **颜色不能是唯一的信号。** 逾期除了橙色还有 `!` 旗标，新题除了绿条还有 `+`。
   8% 的男性有色觉差异，而且分享卡会被转成灰度。
2. **一个层级最多动两样。** 字号、字重、颜色里挑两个，三样齐动就从"有序"
   变成"吵"。
3. **主题切换只重新指派 token，不重写规则。** 设计稿里 `[data-appearance]`
   就是这么做的——27 条浅色覆盖规则被一次 token 重指派取代。

## 3. 字体

### 3.1 字族

| token | 栈 | 用途 |
|---|---|---|
| `--sans` | `-apple-system, BlinkMacSystemFont, "SF Pro Text", …` | 界面。绝大多数文字 |
| `--serif` | `"Iowan Old Style", Charter, Palatino, Georgia, "Songti SC", serif` | 登录页标题、文档标题。中文落到宋体 |
| `--mono` | `ui-monospace, SFMono-Regular, "SF Mono", Menlo, …` | 代码、题号、设备码 |

衬线只用在"这是一段话"的地方，不用在界面控件上。中文走宋体是刻意的——
和刷题界面通用的无衬线拉开，让登录页读起来像一句人话而不是一个系统提示。

### 3.2 字阶

**这是本文档的核心决定。** 25 档收成手机 8 档、面板 6 档。

| token | 手机 | 面板 | 用途 | 依据 |
|---|---|---|---|---|
| `--t-display` | **28** | — | 抽屉大数字 | iPhone 12 mini 满屏实测 |
| `--t-hero` | **26** | **20** | 登录页标题（衬线） | 手机取 iOS Large Title 档；面板按自身字阶顶格 |
| `--t-title` | **18** | **15** | 区块标题、卡片头 | flomo 实测 署名 ÷ 大数字 ≈ 0.64，28×0.64≈18 |
| `--t-body` | **16** | **13** | 正文 | flomo memo 正文实测 16；面板按桌面惯例 13 |
| `--t-reading` | **14** | 13 | 衬线正文、分母 | 登录页那三行 |
| `--t-label` | **13** | **12** | 行标题、按钮、导航 | |
| `--t-meta` | **12** | **11** | 时间、计数、出处 | flomo 标签计数实测 12 |
| `--t-micro` | **11** | **10** | 难度、状态、角标 | 全大写 + 字距时的下限 |

**没有小数。** 现在的 `10.5 / 11.5 / 12.5 / 13.5 / 14.5` 全部消失——
它们来自两处 `.86em` / `.8em` 的相对单位，没有人挑过这些值。

**相对单位禁用于字号。** `em` 会让字号依赖 DOM 嵌套深度，同一个组件
放进不同容器就变大小。字号必须是 token，不能是算出来的。

### 3.3 行高

行高按**用途**分，不是一个值：

| token | 值 | 用在 |
|---|---|---|
| `--lh-tight` | 1.2 | display、hero —— 大字要紧凑，不然散架 |
| `--lh-snug` | 1.4 | title、label、meta、micro —— 界面文字要可预测 |
| `--lh-body` | **1.7** | 正文 —— flomo 实测 16/27 = 1.69 |
| `--lh-reading` | 1.9 | 衬线段落 —— 登录页、长正文 |

1.7 比常见的 1.5 松。这是对着 flomo 量的，不是拍的：那是一个"读自己写的
东西"的产品，比"扫一眼信息"的界面需要更多呼吸。

### 3.4 字重

**只用四档**，而且第四档只给衬线：

| token | 值 | 用途 |
|---|---|---|
| `--w-regular` | 400 | 正文、说明。默认 |
| `--w-medium` | 500 | 轻微强调、行标题 |
| `--w-semi` | 600 | 选中态、区块标题、唯一要被看见的那个字 |
| `--w-bold` | 700 | **仅衬线 hero**。无衬线界面里不出现 700 |

不用 300 和 800+：前者在小字号上发虚，后者在界面里永远过重。

一个重要后果：**选中态用 600 会改变文字宽度。** 设计稿里导航每项预留了
固定宽度（`min-width: 30px`），就是为了防止"哪一项被选中"改变整条导航的
排布。凡是用字重表示状态的地方都要预留。

### 3.5 字距

| 场景 | 值 |
|---|---|
| 正常文字 | `normal`（不写） |
| display / hero（≥20px） | `-0.5px` —— 大字默认偏松，要收 |
| 全大写小标签（micro） | `+0.09em` —— 大写字母间需要空气 |

全大写 + 大字距的标签必须配 600 字重。小字号 + 大字距本来就稀，再用 400
会散成一排灰点。

### 3.6 规则

1. 字号必须来自 token，不准出现字面量，不准用 `em`/`%`。
2. 行高跟着用途选，不跟着字号算。
3. 一个层级最多动 {字号, 字重, 颜色} 中的两样。
4. 衬线只用于成段的话，不用于控件。

## 4. 间距

4px 栅格。已有且不改：

| token | 值 | 典型用途 |
|---|---|---|
| `--s1` | 4 | 图标和文字之间、标签内距 |
| `--s2` | 8 | 紧凑行内距、按钮组间隙 |
| `--s3` | 12 | 面板里的卡片内距 |
| `--s4` | 16 | 标准块内距、手机卡片间隙 |
| `--s5` | 20 | 面板左右内距 |
| `--s6` | 24 | 手机屏左右内距 |
| `--s7` | 32 | 大区块之间 |
| `--s8` | 40 | 屏级分隔 |

**密度是分平台的**，用同一套 token 的不同档表达：

| | 手机 | 面板 |
|---|---|---|
| 屏/面板左右内距 | `--s6` 24 | `--s5` 20 |
| 卡片内距 | `--s4` 16（登录条目 17，见 §10） | `--s3` 12 |
| 同组元素间隙 | `--s4` 16 | `--s2` 8 |

间距不准出现 token 以外的值。唯一的历史例外是登录条目的 17 和卡片的 17，
来源是 flomo 实测——见 §10 已知偏离。

## 5. 圆角

| token | 值 | 用途 |
|---|---|---|
| `--r1` | 4 | 小药丸、标签、复选框 |
| `--r2` | 8 | 按钮、菜单项 |
| `--r3` | 12 | 面板里的卡片、输入框 |
| `--r4` | 16 | 手机卡片、分享卡 |
| `--r5` | 18 | 大容器 |
| `--rp` | 999 | 胶囊 —— 分段控件、间隔阶梯 |

规律：**容器越大，圆角越大**。嵌套时内层圆角 ≈ 外层 − 内距，否则内外两条
弧对不上，视觉上会"挤"。

## 6. 尺寸与点击区

| | 手机 | 面板 |
|---|---|---|
| 最小点击区 | **44×44pt**（iOS HIG 硬性） | **28×28px** |
| 列表行高 | 40（flomo 实测 40.2） | 36 |
| 标题栏 | 52 | **36** |
| 主按钮高 | 48 | 32 |
| 图标 | 20 | 16 |

**手机的行高 40 低于 44pt 的触控下限，这是故意的。** 视觉密度按 40 画，
可点区域靠 `contentShape` 向外扩到 44 —— 不要为了凑触控下限把行撑高，那会
让整个列表变松。

面板用 28 是因为指针设备的精度远高于手指，桌面 UI 普遍在 24–32 之间。

## 7. 层次

只有两档阴影，没有第三档：

| token | 用途 |
|---|---|
| `--lift` | 轻微浮起 —— 浮在底色上的药丸、图标组 |
| `--shadow` | 真正的浮层 —— 菜单、弹层、分享卡 |

层次优先用**背景色差**（ground / card / inset）表达，阴影是补充。深色模式
下阴影几乎不可见，只靠阴影分层的界面在深色下会糊成一片。

## 8. 动效

| token | 值 |
|---|---|
| `--ease` | `cubic-bezier(.22, .61, .36, 1)` |

时长：进场 420ms（抽屉）、状态切换 180ms、微反馈 120ms。

必须响应 `prefers-reduced-motion: reduce`，把 transition 关掉而不是缩短。

## 10. 已知偏离

系统的可信度取决于例外是被记录的还是被偷偷留下的。目前有三处：

1. **登录条目内距 17 而非 16。** 来源是 flomo 实测。17 不在 4px 栅格上。
   **处置**：下次改版归到 `--s4` 16，除非实测证明 1px 有感知差异。

2. **手机行高 40 低于 44pt 触控下限。** 见 §6，这是刻意的，靠可点区外扩补偿。
   **处置**：保留，但 iOS 实现时必须确认外扩真的做了。

3. **绿底白字 2.03:1。** 设计稿里记为"明知故犯"。
   **处置**：本文档 §2.3 已推翻——改成绿底深墨字 7.90:1，品牌色不变。
   设计稿待同步。

## 11. 这些数是怎么来的

方法论，供以后加新值时follow：

- **平台给的**：iOS 正文 17pt、触控 44pt、Web 16px。这些不要自己发明。
- **实测参考**：flomo 的截图逐张标定缩放比后量出来的——28、18、16、
  16/27 的行高、40.2 的行高、12 的计数。量一个你认可的产品再决定抄不抄，
  比"我觉得 24 看起来对"可靠得多，因为对方那个值是真用户用出来的。
- **算出来的**：所有对比度。颜色不靠眼睛判断，浅色模式的 ink-3 看起来
  "挺清楚"，算出来 2.39:1。
- **栅格约束**：间距落 4 的倍数，字号落整数。

没用纯模数音阶（1.2 / 1.25 那种）。比例会给出 20.48 这类数，而屏幕要整数、
行高要落 4px 栅格。实际做法是**比例定方向，手工凑到整数**。
