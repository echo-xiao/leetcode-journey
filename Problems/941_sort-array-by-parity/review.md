# 941. 按奇偶排序数组 · 复盘

parity是奇偶性的意思，这个题目其实就是左边奇数、右边偶数，也不用再排序，所以整个数组是不用排序的。题目也直接说了，return any array，所以可以直接创建一个新的array，但是也会想是不是可以直接原地排序，从而想到是否可以用快慢指针，slow指针用来维护even数组，fast指针用来判断是否是even数组，实际上是可以的，但是这个里面就肯定不是覆盖了，而是交换，但是这个就会有一个疑惑，那么slow指针维护的是下一个可以填充的位置，也就是先交换，slow指针再前进，如果slow指针指向的也是偶数呢？但是好像又不会，因为这个区域已经被fast探索过了，所以slow指针指向的肯定不会是偶数，一定是奇数，所以就可以进行互换，yes and no，最常见的情况是odd，但也有可能是偶数，`当slow==fast的时候`，这基本上只能是数组开头的部分，遇到的都是连续的even。然后我题目实际上的是另外一种解法，用的对撞指针，除了原地充足，这个题目还满足一个条件就是左边even右边odd，直觉上感觉可以直接用对撞指针，其实如果总结下来就是这类分区问题，对撞指针就是很好的技巧，分区的本质就是把一个无序的数组，整理成两个、多个分区。那么来试试看，终止条件用的肯定是while left<right的条件，当left指向odd，并且right指向even的时候进行互换，那么这个里面的条件就会有几种：第一种情况，left指向odd，right指向even；第二种情况，left指向even，right指向odd；第三种，都指向even；第四种：都指向odd；分四种进行进行分析，然后进行状态的恢复，那么这个里面动作指针移动的顺序，由于判定情况只依赖于外界条件，所以指针指向的是下一个空位置，先交换再移动指针，那么为什么只依赖于外界条件，就是指针指向下一个空位置呢？因为不用回头看/回头进行判定，所以可以是下一个位置，所以先直接交换了，再移动。如果要进行回头看/判定的情况，就不能够先交换/覆盖了，不然就没有了，所以先判定完了之后，先走一步，再进行交换。但是其实这种顺序更多只是发生在快慢指针这个里面，但是仍然可以借鉴的，因为执行的顺序其实核心都一样，尤其针对需要回头看的情况，假如需要回头进行判定，那么slow就是已经维护数组的最后一节，要处理的是最后一节的下一位，所以先要走一步，再进行移动，然后在不需要回头看的情况下，slow维护的是下一个空位置，这个空位置一定是个坏东西，所以先需要替换，然后再移动slow指针。总结下来就是：如果要回头看的场景，slow就是站在维护好的数组最后一个位置上，需要先走再放置，因为这个位置已经是已经确认的、正确的好东西，但是不回头看的场景，是站在下一个空的位置上的，而这个位置一定是需要处理的坏东西，因为好东西已经被fast判断处理掉了，所以需要先放置/交换，然后再移动。最后回头这个问题，这四种状况分析完了之后，看看是否可以进行合并和化简。
