# 145. 二叉树的后序遍历 · 复盘

**两种思考方式，**后续遍历跟前序和中序遍历会有一些不一样，需要思考遍历完整个左子树和右子树，**这个正向思考的过程会死机，因为以某种方式等right子树走完，就会死机，当pop一个节点的node的时候，代码是无法区分left是否已经处理完毕**，是刚从left回来吗？如果是的话，就需要去right并且不能够append，是刚从right回来吗？如果是的话，说明left和right都走完了，这种情况下才能append，所以只是pop一个节点的时候，代码需要区分这两种情况，需要用到逆向思维。区分这两种情况，需要引入额外的变量prev，来记录上一个访问的节点，去回忆是从哪里来的，这样状态机会非常的复杂和混乱。解决的方式就是先解决它的反面，从根→右→左，所以其实按照前序遍历的逻辑，输出结果，但是最后把结果反过来就行。**那么如果我一定要正向思考呢？**需要引入一个prev变量，用来告诉你的代码，你是从left过来的，还是从right过来的。在要对node进行处理的时候，要知道是从left回来还是从right回来的，如果从left回来，就变了中序遍历，但是如果从right回来的，就知道right已经遍历完了，现在处理node是后续遍历。**这个里面四个知识点：** 1. peek = stack[-1]，这个**peek其实是父节点**，因为while loop的时候，append是父节点，然后curr是父节点的子节点，是先驱游击节点 2. **prev 是 peek 的子节点，**因为想要知道的peek从哪里来？是从哪个子节点过来的，所以比较的是 peek.left or peek.right 是否等于 prev 3. **为什么是peek做决策呢**？因为他是当前被暂停的、等待left和right完成的父节点，只有他有资格决定自己什么时候被pop出去 4. **做决策的时候实际上有三种方式**，一种是right待处理，也就是peek.right 存在且不等于prev，一种是已经完成 peek.right 等于prev，一种是peek.right 等于none，不是两种情况 peek.right==prev或者peek.left==prev，**这个里面其实就是两种情况**，首先left已经走完了，在while loop里面已经处理完了，所以peek只有两种可能，一种是right还没有去过，没去过就要去，一种是right已经走完了/不存在，那么就需要处理当前节点。
