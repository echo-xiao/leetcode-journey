# 3616. 使数组元素等于零 · 复盘

这个题目如果 brute force 是 **#simulation** 的过程，里面的结构分成三层，第一层是要找出发点，然后执行专项，第二层是 to left 或者 to right 的具体执行， 最后一层是判断是否全部为0。第一层找出发点是通过遍历所有为0的元素，然后需要执行 left 或者 right，这个 left 或者 right 不是执行细节里面的转向，而是找到起点之后就需要左边尝试一下右边尝试一下，这个里面都需要尝试一遍，因为是两种不同的方案，如果执行通过了 cnt +=1 ，返回一共成功的次数，这就是整个第一层的结构。第二层是具体方向的执行，这个函数里面，又分成3层，首先是初始状态的设置（数组、起始点、方向），然后，但是这个具体方向的执行是指当元素的value>0的时候，有三个动作，分别是消耗一个金币，元素值-1，然后转向，然后再往前走一格，这个里面的转向就是用direction *= -1 来替代的，然后往前走一步就直接是curr += direction了，另外一种当这个元素值为0的时候，由于是直接划过去，所以跟curr += direction是一致的，这个里面是用一个while loop来进行操作的，只要在这个数组里面就可以，最终返回判断数组是否为0。最后一层是判断是否数组全部为0，其实就是遍历一遍就好了。**#前缀和 **刚刚的simulation是最直观的解法，但是这道题目是easy，其实就是因为里面有巧妙的解法，这个过程就是一个碰左边再碰右边的过程，每碰一次就会有一次的消耗，这个消耗就是前缀和和后缀和的消耗，所以这个解法就会分成两层，一层是直接求出来前缀和和后缀和，一层是判断前后缀是否相等。前缀和容易计算，后缀和这里有一些tricky的地方。二层是每一个solution要进行判断，如果不是0，那么就不是起始点，那就要重新来，如果是0，就继续往下走，也就是要判断是完美的对称还是不完美的对称，同时完美的对称计数2次，因为左边和右边都能够走，右边是不完美的对称，因为只能选择一边走，所以计数1次。酱紫
