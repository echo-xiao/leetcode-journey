# 88. 合并两个有序数组 · 复盘

两个已经排好顺序的array，来进行merge，肯定用双指针从每个的array进行走就好了，但是为什么这个题目让我想到merge两个sorted linked list呢？先单独看这个题目，很明确到底是merge到哪个array which is num1，那么这个里面就是涉及到排序里面，你先找最大还是找最小，因为是原地array的排序，所以肯定不能够是直接覆盖掉，所以肯定是用交换，因为num1后面有一些空位置，所以肯定就是先找大的数字，以及提供了n是多少，就可以定位到每个数组最后一个实际要比较的数字。所以可以理解为从最后一个位置开始，然后直接覆盖。所以其实还是覆盖而不是交换，是不是交换的话，会变得非常麻烦，为什么我一直会想到交换呢？是因为排序里面有swap吗？因为有很多排序如果是原地重组，并且没有额外的空间，那么肯定就是交换，但是这个里面留出了额外的空间，所以肯定是直接覆盖，找到大的，然后覆盖掉。那么这个里面是否需要三个指针呢？不论如何起码需要三个索引的位置吧：第一个是nums1的末尾位置，用来放置的i，第二个是nums1的实际数字比较的末尾p1，第三个是nums2的末尾p2，nums1的末尾位置的指针用来遍历全数组。因为直接遍历，所以可以选择用for loop，for的是nums1的末尾位置i，然后里面就有判断条件，哪个大就放哪个位置，然后放置了之后，指针就进行移动就好，所以其实就是需要用3个指针，逻辑不难，但是里面有判断条件需要注意的：当有两个数组的时候，都需要判断收尾工作，以及是否有剩余元素，理想的情况肯定是一套逻辑直接判断是否有剩余元素，这种时候，如果要直接想到这个数组的处理，需要思考这个里面的判断条件是两个数组里面都有元素可比，那么当没有可比情况的时候怎么办？所以其实是三种情况：第一种是每个array都有元素出来可以比较，第二种是nums1没有元素了，只剩下nums2了，第三种是nums2没有元素了，只剩下nums1了。把三种条件清晰的列出来，判断怎么做，然后再去思考两个数组可以比较的情况，这个思维过程就会直接转换成一个if elif else的结构，而if elif else的条件是顺序的，通过“顺序检查”和“一旦命中就停止”的规则，如果条件之间没有优先级的原则，那么条件之间最好是天然互斥的，这样的思考就是全面的并且没有遗漏条件的。
