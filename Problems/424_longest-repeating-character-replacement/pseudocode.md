# 424. 替换后的最长重复字符 · 解题思路与伪代码

## 1. 一句话直击本质
**维护一个滑动窗口，窗口内"非最多重复字符数"（即需要替换的字符数）不超过 k，通过动态跟踪窗口内出现次数最多的字符频次来判断窗口是否合法，并记录窗口的最大长度。**

## 2. 综合思路

所有版本本质上都是**滑动窗口 + 哈希计数**，核心差异在于**如何获取/维护窗口内的最大字符频次**，分为两种思路：

**思路 A：实时精确计算最大频次（版本 1、2、3）**
- 每次移动右指针后，都重新计算当前窗口内所有字符的最大出现次数（`max(counter.values())` 或手动遍历）。
- 当 `窗口长度 - 最大频次 > k` 时，收缩左指针，直到窗口重新合法。
- 保证窗口长度合法性是"精确"的，但需要额外的 O(字符集大小) 开销来求最大值。

**思路 B：懒惰更新最大频次（不回退），只增不减（版本 4）**
- 维护一个 `maxCount` 变量，它只在遇到更大频次时更新，从不因为窗口收缩而重新计算变小。
- 当窗口大小减去 `maxCount` 超过 k 时，只将窗口收缩 1（不是循环收缩到满足条件，因为 `maxCount` 是历史最大值），从而保证窗口大小单调不减，最终结果依然正确。
- 这是更优化的写法，因为不需要每次重新扫描求最大值，时间复杂度更低。

两种思路本质相同：**只要窗口内某个字符出现次数达到过 m，就有可能把窗口长度扩展到 m+k**，因此结果的正确性可以保证，即使不精确追踪当前窗口最大值也不影响最终答案。

## 3. 全量伪代码

```
函数 characterReplacement(s, k):
    初始化 counter 为空哈希表      # 记录窗口内每个字符出现次数
    left = 0
    maxCount = 0                  # 窗口内出现过的字符最大频次（可能是历史值）
    maxLen = 0

    for right in 0 .. len(s)-1:
        c = s[right]
        counter[c] += 1

        # ---- 版本差异点 ----
        情况A（版本1/2/3）：
            实时计算 curMax = counter中所有值的最大值
            while (right - left + 1) - curMax > k:
                counter[s[left]] -= 1
                if counter[s[left]] == 0: 删除该键
                left += 1
                重新计算 curMax = counter中所有值的最大值
        
        情况B（版本4）：
            maxCount = max(maxCount, counter[c])   # 只增不减
            if (right - left + 1) - maxCount > k:
                counter[s[left]] -= 1
                left += 1
                # 不重新计算 maxCount，允许窗口长度整体不减小

        maxLen = max(maxLen, right - left + 1)

    return maxLen
```

## 4. 复杂度

**思路 A（版本1/2/3，实时求最大值）：**
- 时间复杂度：$O(n \times \Sigma)$，其中 $\Sigma$ 为字符集大小（如26），因为每次移动指针都要遍历哈希表求最大值。
- 空间复杂度：$O(\Sigma)$

**思路 B（版本4，懒惰更新最大值）：**
- 时间复杂度：$O(n)$，每个字符最多被访问常数次。
- 空间复杂度：$O(\Sigma)$

（若 $\Sigma$ 视为常数 26，两者时间复杂度均可近似记为 $O(n)$，但版本 B 是理论上更优的实现。）
