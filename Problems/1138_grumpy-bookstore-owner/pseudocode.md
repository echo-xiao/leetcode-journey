# 1138. 爱生气的书店老板 · 解题思路与伪代码

## 1. 一句话直击本质

**滑动窗口**：固定收益（老板不生气时的顾客数）加上大小为 `minutes` 的滑动窗口内"消气"能挽回的最大顾客数（即窗口内老板生气时流失的顾客数最大值）。

## 2. 综合思路

本题解法主要围绕**滑动窗口**技巧展开，核心思想一致，仅在实现细节上可能有差异：

- **两遍扫描 + 滑动窗口（本题解法）**：
  1. 先计算不生气时段的固定满意顾客数 `fixed`。
  2. 用滑动窗口维护长度为 `minutes` 的区间内，"生气"时段能挽回的顾客数 `flex`。
  3. 窗口滑动过程中动态增删首尾元素，实时更新最大值。

- **前缀和 + 枚举窗口（等价思路，未在代码中出现但常见）**：
  先计算 `grumpy[i]*customers[i]` 的前缀和，然后枚举窗口起点，用前缀和差值 O(1) 求窗口内可挽回顾客数，最终答案为 `fixed + max(窗口内可挽回值)`。二者本质相同，只是求窗口和的方式不同（滑动 vs 前缀和）。

两种思路时间复杂度相同，均为线性扫描，区别仅在于用**增量更新**还是**前缀和差值**来求窗口内的和。

## 3. 全量伪代码

```
函数 maxSatisfied(customers, grumpy, minutes):
    n = customers 的长度
    fixed = 0       # 老板不生气时的固定顾客数
    flex = 0        # 当前窗口内，老板生气时可挽回的顾客数

    # 第一步：统计所有不生气时段的顾客数（固定部分，不随窗口变化）
    对 i 从 0 到 n-1:
        如果 grumpy[i] == 0:
            fixed += customers[i]

    # 第二步：初始化第一个窗口 [0, minutes-1] 内生气时段的顾客数
    对 i 从 0 到 minutes-1:
        如果 grumpy[i] == 1:
            flex += customers[i]

    maxres = fixed + flex   # 记录当前最大满意顾客数

    # 第三步：滑动窗口，窗口右移一位，加入新元素，移除旧元素
    对 i 从 minutes 到 n-1:
        如果 grumpy[i] == 1:            # 新进入窗口的元素若是生气时段则加入
            flex += customers[i]
        如果 grumpy[i-minutes] == 1:    # 移出窗口的元素若是生气时段则减去
            flex -= customers[i-minutes]

        res = fixed + flex
        maxres = max(maxres, res)

    返回 maxres
```

## 4. 复杂度

- 时间复杂度：$O(n)$，其中 $n$ 为数组长度，只需两次线性扫描（一次统计固定值，一次滑动窗口）。
- 空间复杂度：$O(1)$，只使用了常数个额外变量（`fixed`、`flex`、`maxres`），未使用额外数组。
