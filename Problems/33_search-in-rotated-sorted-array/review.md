# 33. 搜索旋转排序数组 · 复盘

**分析一，**这给题目的逻辑其实是三层，1. 判断是否命中target 2. 判断是平路还是悬崖 3. 只在平路进行判断，如果是悬崖，不做判断。另外，这个里面需要判断什么时候要加上等号，什么时候不要加上等号。while left ≤ right，表示不要漏掉最后一个元素，target ≤ … 范围的判断，边界加上等号是因为需要考虑边界, nums[left] ≤ target，必须有等号，因为target可能是区间的开头，target ≤ nums[mid] 不需要等号，因为一开始就判断了等号的条件，同理右边。nums[left] ≤ nums[mid] 判断有序，处理只剩下两个数的尴尬情况。**分析二，**其实逻辑很好理解，两层，一层用来找到pivot点，找到这个点就可以把左边和右边分别变成有序的序列，然后判断target在哪里，分别做标准的binary research精准找到target。那么这样找pivot点的难点在于**1. 跟谁比，以及2. pivot的值到底是哪个？如何存起来。3. 最后相等的时候，right=mid-1. **首先这个跟谁比，不是跟target比较，因为跟target无关，而是跟nums[-1]比较，为什么是跟num[-1]比较呢？其实就是跟nums[0]和num[-1]进行比较，但是找pivot其实是找这个nums里面的最小值，跟nums[0]找是不对的，因为这个不是异常；为什么不是跟left和right对应的值比较呢？因为left和right一直在不断的变化。如果用while left ≤ right，也需要判断什么时候储存pivot，虽然mid可能是最小值，但是为了能够让循环结束，满足left>right的情况，我要把mid踢出圈子，所以要往左边走，需要先保存。最后相等时候right=mid-1，其实就是要往左边走的意思。**为什么要存值：8、9、1、2、3、4、5，和8、9、10、2、3、4、5，这个里面就是2是不是最小值，如果跟nums[-1]比较，如果比它大，就可以丢掉，但是如果比它小，往左走也不一定能够知道这个对应的值是什么方向。**
