# 167. 两数之和 II - 输入有序数组 分析

## 1. 一句话直击本质
利用数组**有序**的性质，通过双指针从两端向中间收缩，根据当前和与目标值的大小关系决定移动左指针或右指针，从而在 $O(n)$ 时间内找到答案。

## 2. 综合思路

所有 4 个版本本质上都是**对撞双指针（Two Pointers）**解法，没有使用哈希表等其他数据结构，细微差异仅在于：

- **循环终止条件**：版本1、2使用 `left < right`；版本3、4使用 `left <= right`（多一次冗余判断，但由于相等时 `numbers[left]+numbers[right]` 会被计算两次左右相同元素之和，不影响正确性，因为题目保证有唯一解且 left≠right 时才成立，多出的判断不会误判）。
- **未找到时的返回值**：版本1返回 `[]`，版本2返回 `None`，版本3、4返回 `[-1, -1]`（均为兜底逻辑，实际题目保证有解，不会触发）。
- **版本4冗余计算**：多计算了一个 `mid` 变量，但**从未使用**，属于无效代码，不影响逻辑和复杂度。

核心算法思路唯一：**双指针收缩法**。

## 3. 全量伪代码

```
函数 双指针求两数之和(numbers, target):
    初始化 left = 0
    初始化 right = numbers长度 - 1

    当 left < right (或 left <= right):
        计算 sumVal = numbers[left] + numbers[right]
        
        如果 sumVal 等于 target:
            返回 [left+1, right+1]   # 题目要求下标从1开始
        否则如果 sumVal 大于 target:
            right 减 1   # 和过大，右指针左移，减小和
        否则:
            left 加 1    # 和过小，左指针右移，增大和

    返回 未找到的兜底值（[]、None 或 [-1,-1]）
```

**正确性依据**：数组升序排列，若当前和大于target，说明right对应的数偏大（因为已是当前范围最大值组合的一部分），右指针左移；反之左指针右移。每次移动都排除了一个不可能再参与最优解的边界，保证不遗漏正确答案。

## 4. 复杂度

- **时间复杂度**：$O(n)$，其中 $n$ 为数组长度，双指针最多各遍历一次数组。
- **空间复杂度**：$O(1)$，只使用了常数个额外指针变量，未使用额外数据结构。
