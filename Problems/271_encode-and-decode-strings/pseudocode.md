# 字符串编码与解码算法分析

## 1. 核心逻辑一句话总结

**在每个字符串前添加其长度信息作为分隔标记（长度+特殊分隔符+内容），解码时先读长度再按长度精确截取，从而避免字符串内容本身包含分隔符导致的歧义问题。**

## 2. 综合思路

所有 AC 版本采用完全相同的核心策略——**长度前缀法（Length-Prefixed Encoding）**，未出现其他解法分支（如分隔符转义法、Base64编码法等）。具体思路统一为：

- **编码阶段**：遍历字符串列表，对每个字符串记录 `长度#内容` 的格式拼接成一个大字符串。
- **解码阶段**：使用双指针（`i` 标记当前字符串起始位置，`j` 用于寻找 `#` 分隔符位置），先解析出长度数字，再根据长度截取对应内容，重复该过程直至遍历完整个字符串。

四个版本仅在变量命名、代码格式上存在细微差异，逻辑完全一致，属于同一实现范式的不同书写。

## 3. 全量伪代码

```
类 Codec:

    函数 encode(字符串列表 strs) -> 字符串:
        初始化结果字符串 res = ""
        对于 strs 中的每个字符串 s:
            res += (s的长度转字符串) + "#" + s
        返回 res

    函数 decode(编码字符串 s) -> 字符串列表:
        初始化结果列表 res = []
        初始化指针 i = 0
        当 i < s的长度:
            设 j = i
            当 s[j] 不等于 "#":
                j += 1  // 寻找分隔符位置
            提取长度 length = 将 s[i:j] 转为整数
            提取内容 word = s[j+1 : j+1+length]  // 根据长度精确截取
            将 word 加入 res
            更新 i = j + 1 + length  // 移动到下一个字符串的起始位置
        返回 res
```

## 4. 复杂度分析

设字符串列表共有 $n$ 个字符串，总字符数（所有字符串长度之和）为 $L$。

**编码过程：**
- 时间复杂度：$O(L)$ —— 需遍历所有字符并拼接
- 空间复杂度：$O(L)$ —— 存储编码后的结果字符串（长度前缀增加常数级开销，可忽略）

**解码过程：**
- 时间复杂度：$O(L)$ —— 双指针遍历编码字符串一次，每个字符最多访问常数次
- 空间复杂度：$O(L)$ —— 存储解码后的字符串列表

**综合复杂度：**
$$\text{时间复杂度} = O(L), \quad \text{空间复杂度} = O(L)$$

其中 $L$ 为所有字符串的总长度（该复杂度与字符串数量 $n$ 无直接关系，仅由总字符量决定）。
