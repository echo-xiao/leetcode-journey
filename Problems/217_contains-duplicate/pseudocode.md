# 217. 存在重复元素 · 解题思路与伪代码

# 存在重复元素 - 算法分析

## 1. 一句话直击本质
**利用哈希集合的唯一性特征，在一次遍历中检测数组中是否存在重复出现的元素。**

## 2. 综合思路

针对本题，常见的 AC 解法主要有以下几类思路：

- **哈希集合法（本题采用）**：边遍历边将元素插入 `set`，插入前先检查该元素是否已存在，一旦发现重复立即返回 `True`，兼顾时间效率与提前终止的优化。
- **排序法（对比思路）**：先对数组排序，再遍历比较相邻元素是否相等，若相等则存在重复。此法时间复杂度为 $O(n\log n)$，但空间复杂度可优化至 $O(1)$（原地排序）。
- **集合大小比较法（对比思路）**：直接比较 `len(set(nums))` 与 `len(nums)` 是否相等，若不相等说明存在重复。此法代码简洁，但无法提前终止，且需要额外遍历构建整个集合。

本题给出的版本 1 属于**哈希集合法**，且做了提前返回的优化（一旦发现重复立刻终止，无需遍历完整个数组）。

## 3. 全量伪代码

```
函数 判断是否存在重复元素(数组 nums):
    初始化空集合 seen

    对于 nums 中的每一个元素 i:
        如果 i 已经存在于 seen 中:
            返回 True   # 发现重复，提前终止

        将 i 加入 seen 中

    返回 False   # 遍历结束仍未发现重复
```

（其他等价思路伪代码，作为对比补充）

```
# 排序法
函数 判断是否存在重复元素_排序版(数组 nums):
    对 nums 进行原地排序

    对于 i 从 0 到 len(nums)-2:
        如果 nums[i] 等于 nums[i+1]:
            返回 True

    返回 False
```

```
# 集合大小比较法
函数 判断是否存在重复元素_集合版(数组 nums):
    返回 (集合(nums) 的长度) 不等于 (nums 的长度)
```

## 4. 复杂度

**版本 1（哈希集合法，本题实现）：**
- 时间复杂度：$O(n)$，其中 $n$ 为数组长度，每个元素的插入与查找操作均摊为 $O(1)$
- 空间复杂度：$O(n)$，最坏情况下集合需存储所有 $n$ 个不重复元素

**排序法（对比）：**
- 时间复杂度：$O(n\log n)$，主要由排序决定
- 空间复杂度：$O(1)$ 或 $O(\log n)$（取决于排序算法的实现，如原地快排的递归栈开销）

**集合大小比较法（对比）：**
- 时间复杂度：$O(n)$
- 空间复杂度：$O(n)$
