# 985. 令牌放置 · 解题思路与伪代码

## 一句话本质
**贪心+双指针**：排序后优先用最小代价的令牌换取分数，当无力购买时用当前最大分数（若有）换取能量，以求最终获得的最大分数。

## 综合思路

本题的核心是贪心策略：**要使分数最大化，应尽量用最少的能量换取分数（拿最小的token正面），当能量不足时，则消耗一个已获得的分数来换取最大的能量（拿最大的token反面）**。

所有 AC 版本基本采用同一种思路——**排序 + 双指针贪心模拟**，具体分支：

1. **双指针贪心（唯一主流解法）**：
   - 先将 tokens 排序。
   - 用左指针 `left` 指向最小的令牌，右指针 `right` 指向最大的令牌。
   - 若当前能量足够买入左边最小令牌，则消耗能量、获得1分，同时更新最大分数。
   - 否则如果当前已有分数（score≥1），则用一分换取右边最大令牌的能量。
   - 若两种操作都无法进行（能量不足且没有分数可以兑换），则终止循环。
   - 最终返回过程中出现过的最大分数 `maxscore`（因为“卖分数换能量”操作会使分数暂时下降，所以要保留历史最高值）。

由于本题数据规模和逻辑较简单，未出现动态规划、BFS/DFS 等复杂解法，各语言/各用户提交版本本质上均为该贪心双指针法的不同实现（Python、C++、Java等语法差异，逻辑完全一致）。

## 全量伪代码

```
函数 bagOfTokensScore(tokens, power):
    将 tokens 从小到大排序
    n = tokens长度
    left = 0
    right = n - 1
    score = 0
    maxscore = 0

    当 left <= right 时循环:
        如果 tokens[left] <= power:              # 能量足够买入最小令牌
            power -= tokens[left]
            score += 1
            left += 1
            maxscore = max(maxscore, score)       # 更新历史最大分数
        否则如果 score >= 1:                      # 能量不足，但有分数可以卖出换能量
            power += tokens[right]
            score -= 1
            right -= 1
        否则:
            跳出循环                              # 无法继续操作，结束

    返回 maxscore
```

## 复杂度

- 排序操作为 $O(n \log n)$，双指针遍历为 $O(n)$，因此总体时间复杂度为：
$$O(n \log n)$$

- 空间复杂度（除排序本身消耗外，仅用常数额外变量）：
$$O(1)$$（若考虑排序所需辅助空间，视语言实现可能为 $O(\log n)$ 或 $O(n)$）
