# 数组的最大美丽值 —— 算法分析

## 1. 一句话直击本质
将每个数视为区间 $[nums[i]-k, nums[i]+k]$，排序后用**滑动窗口**寻找能被同一个数值覆盖的最长子区间（即窗口内最大值与最小值之差不超过 $2k$）。

## 2. 综合思路
本题的核心思路只有一种主流高效解法，但可以从不同角度理解：

- **排序 + 双指针（滑动窗口）思路**：
  将数组排序后，问题转化为求最长的连续子数组，使得子数组内最大值与最小值之差 $\le 2k$（因为若两数经过 $\pm k$ 调整后能相等，则原始差值最多为 $2k$）。使用左右指针维护一个满足条件的窗口，右指针不断右移扩展，当窗口不满足条件时收缩左指针，过程中记录最大窗口长度。

- **等价理解（区间选点/差分思路，虽未在代码中体现，但为本题常见变体）**：
  也可转化为区间调度问题——每个数扩展为区间 $[nums[i]-k, nums[i]+k]$，求最多有多少个区间存在公共交点，可用差分数组或排序+扫描线实现。但本题给出的 AC 版本均采用排序双指针法，逻辑更直接、代码更简洁。

由于本题只提供了一个版本（排序双指针法），未出现递归/DFS/BFS等其他实现方式。

## 3. 全量伪代码

```
函数 最大美丽值(nums, k):
    对 nums 进行升序排序
    n = nums 的长度
    初始化 left = 0, right = 0
    初始化 最大长度 maxlen = 0

    对 right 从 0 到 n-1 依次遍历:
        当 nums[right] - nums[left] > 2*k 时:
            left = left + 1   # 收缩左边界，直到窗口满足条件
        更新 maxlen = max(maxlen, right - left + 1)

    返回 maxlen
```

**核心逻辑说明**：
- 排序后，由于数组升序，`nums[right] - nums[left]` 一定非负，因此可以省略绝对值判断（代码中虽写了 `abs()`，但排序后其恒等价于直接相减）。
- 窗口 `[left, right]` 内所有数经过合适的 $\pm k$ 变换后能否变为同一个值，等价于窗口内最大值（`nums[right]`）与最小值（`nums[left]`）之差是否 $\le 2k$。
- 左指针单调不减，右指针单调递增，因此整体是线性扫描，时间复杂度可控。

## 4. 复杂度分析

- **时间复杂度**：排序需要 $O(n \log n)$，双指针遍历过程中左右指针各自最多移动 $n$ 次，故双指针部分为 $O(n)$。总体时间复杂度为：
$$
O(n \log n)
$$

- **空间复杂度**：排序若使用原地排序（如 Python 的 Timsort 通常需要 $O(n)$ 的辅助空间，但视语言实现而定），双指针部分只需常数额外变量。整体空间复杂度为：
$$
O(\log n) \text{ 或 } O(n) \quad (\text{取决于排序算法的实现细节})
$$

若不考虑排序算法内部实现的额外开销，仅考虑算法逻辑本身所需的额外空间，则为：
$$
O(1)
$$
