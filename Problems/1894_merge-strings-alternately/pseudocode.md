# 交替合并字符串 —— 算法分析

## 1. 一句话直击本质
按索引位置同步遍历两个字符串，逐位交替取字符拼接，短的字符串耗尽后直接拼接另一个字符串的剩余部分。

## 2. 综合思路
本题所有 AC 版本均采用**同一种迭代解法**，逻辑完全一致，未出现递归、双指针分离处理或其他数据结构的变体。核心思路为：

- 取两字符串长度的较大值作为循环次数上界；
- 循环遍历该上界范围内的每个索引 `i`；
- 在每次循环中，先判断 `word1` 是否还有第 `i` 位字符，有则加入结果；再判断 `word2` 是否还有第 `i` 位字符，有则加入结果；
- 通过越界判断（`i < n1` / `i < n2`）自然处理了长度不等的情况，避免了额外的收尾拼接逻辑。

这是一种**单循环、边界判断合并**的写法，相比"双指针 + 最后拼接剩余部分"的写法更简洁，但本质等价。

## 3. 全量伪代码

```
函数 合并交替字符串(word1, word2):
    n1 ← word1 的长度
    n2 ← word2 的长度
    n ← max(n1, n2)
    结果 ← 空列表

    for i from 0 to n-1:
        如果 i < n1:
            结果.append(word1[i])
        如果 i < n2:
            结果.append(word2[i])

    return 将结果列表拼接成字符串
```

## 4. 复杂度

- 时间复杂度：$O(n)$，其中 $n = \max(len(word1), len(word2))$，每个索引位置做常数次判断与拼接操作。
- 空间复杂度：$O(n)$，用于存储结果字符列表（不计返回值本身占用空间时，中间结构也需线性额外空间）。
