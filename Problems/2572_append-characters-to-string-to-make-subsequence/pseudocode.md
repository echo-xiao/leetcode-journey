# 追加字符以获得子序列 - 算法分析

## 1. 一句话本质
用双指针贪心匹配 `t` 在 `s` 中作为子序列能匹配到的最长前缀，剩余未匹配部分即为需要追加的字符数。

## 2. 综合思路

所有 AC 版本本质上都是**双指针（贪心匹配）**思路，仅在代码实现风格上略有差异：

- **版本1（双 while 指针）**：显式维护 `left`、`right` 两个指针，分别遍历 `s` 和 `t`，通过 while 循环同步推进，当字符相等时移动 `t` 的指针。
- **版本2（for 循环 + 单指针）**：用 `for` 遍历 `s` 的每个字符，维护一个指向 `t` 的指针 `i`，当字符匹配且 `i` 未越界时递增 `i`。

两种写法在逻辑上完全等价，只是遍历 `s` 的方式（while vs for）不同，核心都是**只需一次线性扫描，贪心地在 `s` 中寻找 `t` 的最长可匹配前缀**。

## 3. 全量伪代码

```
函数 appendCharacters(s, t):
    初始化指针 i = 0   // 指向 t 中下一个待匹配字符
    遍历 s 中的每个字符 c:
        如果 i 小于 t 的长度 且 c 等于 t[i]:
            i = i + 1   // t 的当前字符被匹配，指针后移
    返回 t 的长度 - i    // 未匹配部分即为需要追加的字符数
```

**说明**：
- 由于 `s` 只需单向扫描一次，`t` 的指针只会递增不会回退，因此贪心策略是最优的（尽可能早匹配 `t` 中字符，不会影响后续匹配的可能性）。
- 双 while 版本本质是把 for 遍历 `s` 拆分成 `left` 显式指针，逻辑完全一致。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n = |s|$，只需遍历一次 `s`（`t` 的指针最多前进 $|t|$ 次，且 $|t| \le |s|$，故整体仍为 $O(n)$）。
- **空间复杂度**：$O(1)$，只使用常数个额外指针变量。
