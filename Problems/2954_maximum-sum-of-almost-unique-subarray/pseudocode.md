# 《几乎唯一子数组的最大和》算法分析

## 1. 一句话直击本质
**滑动窗口维护固定长度k的子数组，用哈希表统计窗口内不同元素个数，当不同元素数≥m时更新窗口和的最大值。**

## 2. 综合思路

本题本质是"定长滑动窗口 + 哈希计数"问题，AC解法主要围绕以下核心组件展开：

- **窗口和的维护**：用变量累加当前窗口总和，每次滑动时"减去移出元素、加上移入元素"，避免重复求和，保证O(1)转移。
- **窗口内不同元素个数的维护**：用哈希表（defaultdict/unordered_map）记录窗口内每个元素出现的次数。
    - 元素滑入窗口：计数+1。
    - 元素滑出窗口：计数-1，若计数变为0则从哈希表中删除该键（保证`len(counter)`即为不同元素种类数）。
- **合法性判断**：只有当哈希表大小（不同元素个数）≥ m 时，当前窗口和才是有效候选，用其更新全局最大值。

该题一般只有滑动窗口这一种主流解法（区别仅在语言实现细节，如用Counter/dict/unordered_map，是否显式判断窗口越界等），没有本质分叉的DFS/BFS/递归解法。

## 3. 全量伪代码

```
函数 maxSum(nums, m, k):
    初始化 counter = 空哈希表（默认值为0）
    初始化 windowSum = 0
    初始化 maxSum = 0

    // 处理第一个窗口 [0, k-1]
    对于 i 从 0 到 k-1:
        windowSum += nums[i]
        counter[nums[i]] += 1

    如果 counter中不同元素个数 >= m:
        maxSum = windowSum

    // 滑动窗口，从第 k 个元素开始
    对于 i 从 k 到 len(nums)-1:
        // 更新窗口和：加入新元素，移除最左端旧元素
        windowSum += nums[i]
        windowSum -= nums[i - k]

        // 更新计数：新元素计数+1，旧元素计数-1
        counter[nums[i]] += 1
        counter[nums[i - k]] -= 1

        // 若旧元素计数归零，从哈希表中删除，保证键数量=不同元素种类数
        如果 counter[nums[i - k]] == 0:
            删除 counter[nums[i - k]]

        // 判断当前窗口是否满足"几乎唯一"条件
        如果 counter中不同元素个数 >= m:
            maxSum = max(maxSum, windowSum)

    返回 maxSum
```

## 4. 复杂度

- **时间复杂度**：$O(n)$，其中 $n$ 为数组 `nums` 的长度。每个元素最多被加入和移出窗口各一次，哈希表操作均摊 $O(1)$。

- **空间复杂度**：$O(k)$，哈希表最多存储窗口内 $k$ 个不同元素的计数信息（最坏情况下窗口内元素全不相同）。
